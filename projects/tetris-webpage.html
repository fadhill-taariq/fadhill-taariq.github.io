Tetris Webpage

A browser-based take on the classic falling-block puzzle, built from scratch in vanilla JavaScript. No frameworks, no game engine — just a grid, a game loop, and a few carefully tuned rules to capture the feel of Tetris in its purest form.

Role

  • Sole developer

  • One self-contained webpage

The build

The game lives entirely in one webpage. A grid of cells holds the playfield; a game loop drops the active piece on a tick that speeds up with the player's level; keyboard input rotates and shifts pieces while collision rules keep them inside the well. Cleared lines update the score and bump the level. The visuals stay deliberately simple so the timing and feel are what carries the experience.

What I learned

JavaScript
Vanilla JS, end-to-end

Building a non-trivial interactive program without reaching for a framework.

Architecture
The game loop

Separating update, render, and input — the pattern that quietly underpins every game.

Algorithms
Grid math & rotation

Representing pieces, rotating them around the right pivot, and detecting line clears.

Collision
Boundary & piece checks

Stopping pieces from leaving the well or overlapping the stack — the rules everyone forgets to handle.

Input
Keyboard handling

Translating key events into smooth, responsive piece movement.

DOM
Rendering without a canvas

Updating the playfield through the DOM as a forcing function for thinking about performance.

UX
Game feel

The hidden craft of tuning drop speed, level curve, and clear animations so the game feels right.

Discipline
Scope control

Knowing when "Tetris, but…" stops and "Tetris, finished" begins.
